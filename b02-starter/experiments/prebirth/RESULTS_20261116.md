# v2 首次输出前 ID 转接：八文件校准结果

本轮最高零碎度且通过原有整体指标保护的校准方案为 `short_wide`，零碎度 69.8870，比组合方案 65.6586 增加 4.2284 分；未达到 70，不升级为 v3。当前提交版保持冻结，官网既有成绩为 v1 的 75.24，与本表的本地估分区分。

## 固定条件与干预

只使用 train_032、033、050、051、085、144、145、178 八文件。点分类器、1000 步长期记忆关联权重、组合恢复、输出 0.525／0.05 和三次观测确认均不变。新轨首次输出前，用前两次观测及当前点检查与旧轨的运动一致性，再结合既有同目标评分器与双向竞争分差决定是否转接。只使用过去和当圈输入；标签只供外部计分、归因。

先测试活跃旧轨和活跃加退役旧轨，再单独纳入仅输出一两次的短旧轨。短旧轨有独立的 14 圈保留库，不参与原组合方案的常规退役恢复。随后增加一个 1.75 倍运动容差的对照；观察到混轨诊断回退后，再单独把接回概率门槛从 .80 提高到 .95。新目标起批不额外等待。配置、阶段追加理由和保护指标记录在 `protocol.json`，各次不可变源码 ZIP 的 SHA-256 记录在 JSON。这是顺序诊断后的有限追加对照，不是全部在最初预先注册。

## 原因与剩余空间

组合对照有 380 个一两点额外 ID 片段，其中 101 个在该片段开始时是首次发布，279 个此前已经发布。后者中 272 个此前还输出过别的真目标。首次发布的短片段里，74 个当时已有同一真目标的历史 ID，其余是该目标的首次检测。

这说明大量短片段发生在已有 ID 的中途串轨，首次发布拦截覆盖不到这些事件。窄运动门下，本轮仅产生 26 个旧轨候选，单独保留短旧轨也只增加约 0.05 分。把新轨三观测检验使用的运动容差扩大到 1.75 倍后，候选增至 493 个，才出现主要增益；原有常规关联门保持不变。这表明几何覆盖不足是本次方法的重要限制，同时放宽覆盖会增加错误接续，需要保留混轨诊断。

用真值和完整未来回放做追溯诊断，在保留相同输出点、跳过同圈 ID 冲突的条件下，仅修正首次发布的短片段可得零碎度 67.1020，修正全部短片段可得 75.1191。这两组是事后诊断，不是模型成绩，也不是所有因果方法的严格上限；它们表明中途错误归属仍是更大的改进来源。

下一轮应固定本轮候选，重点比较已有 ID 的当前观测是否偏离其长期身份历史，并给原主 ID、竞争 ID 和未匹配项一起做因果决策。训练样本需要覆盖扩大门后的真实候选、实际争抢和短暂串轨，分别检查“阻止串入”与“恢复原主”的贡献。当前阶段停止追加起批阈值组合。

## 复现与产物

`replay.py` 只允许校准名单，可用 `--scene` 单文件复查；`--trace-scene` 指定保存逐圈输出的文件。默认完整八文件。

```text
python experiments/prebirth/replay.py --data FIT64_CAL8.zip --cache CACHE64 --prior MEMORY.pt --affinity AFFINITY.pt --reference COMBINED/summary.json --method short_wide --out runs/prebirth-replay
python experiments/joint_matching/merge.py --parts runs/prebirth-replay --out runs/prebirth-summary --baseline COMBINED/summary.json
```

上述需要既有缓存和训练检查点，不包含于 Git；`--prior` 必须与同目标评分器训练所用文件 SHA-256 相同。原始赛事数据和含点迹的回放 HTML 不上传 Git。聚合证据见 `RESULTS_20261116.json`；本地查看器与分数表入口为 `runs/v2-prebirth/index.html`，并已加入当前成果首页。

本轮没有新增模型训练或 GPU 训练步数，使用缓存点分数在 CPU 上完整回放。冻结 v1 的九项文件、v2 关联运行文件和两份已发布实验权重通过 SHA-256 检查。
