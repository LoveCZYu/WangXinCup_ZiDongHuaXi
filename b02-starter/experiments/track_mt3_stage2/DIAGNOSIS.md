# 第二阶段低召回诊断

结论：定位到置信度不足和预测位置覆盖不足两项直接原因，并修正了单 GPU 训练中真值辅助概率被覆盖的问题。该修正不等于低召回已解决。固定片段可以学会，但迁移到另一文件仍失败；下一步需要验证真实数据训练覆盖、预算和适配设计。

## 可复现的失败信号

使用 pilot02 的 1000 步权重，`diagnostics/probe.py` 通过实际 Handler 和原始点关联路径执行自主回放。固定 train_015 第 100–107 圈，真值 219 点，输出 4 点且全为杂波，命中为 0。缩至第 100 圈仍是 27 个真值、0 命中；从空状态启动该圈同样失败。

命令的项目、上游、数据和权重路径与 README 的云端部署一致：

```bash
python experiments/track_mt3_stage2/diagnostics/probe.py \
  --project /root/shared-nvme/b02/code/b02-stage2 \
  --upstream /root/shared-nvme/b02/code/CNSF-b02-stage2 \
  --data /root/shared-nvme/b02/data/b02-stage2-pilot.zip \
  --checkpoint /root/shared-nvme/b02/runs/b02-stage2-pilot02/inference.pt \
  --out /tmp/b02-repro.json
```

诊断断言为命中率至少 50%，用于捕获本次近零召回症状，不是官方验收线。修正训练调度后再次运行原始八圈复现，结果仍为 0/219，断言仍失败；已有权重的推理未被修改。

## 冻结权重的单变量探针

场景 train_001、002、015、016，先自主回放到第 100 圈，再统计 100–139 圈。前两者属于原训练集，后两者属于开发集；未使用保留集。阈值实验只用于诊断，没有选择新提交阈值。

- 原阈值下，015/016 的命中率分别为 0.16% / 0%。把起批阈值由 .75 单独改为 .5、.25、.1，或在 .25 基础上再把维持阈值改成 .5，都未达到可用召回；所测 016 最多为 2.89%。
- 原推理轨迹上，不考虑任何置信度、对全部预测与真值做门内一对一配对，015/016 的几何覆盖率也仅为 8.79% / 12.32%。这个数是该次推理的几何诊断，不是所有未来策略的召回上界。
- 015 新目标查询的最高概率仅 .392，低于 .75 起批阈值；靠近真值的查询概率中位数 .013，远离真值的为 .009，辨别能力弱。
- 015 的预测—真值距离最小指派中，各维绝对误差中位数约为方位 .0348、距离 .0396、俯仰 .0267。前两项分别大于原始点关联门限 .025、.020；这与低几何覆盖一致，但不能据此断言所有错配都由门限造成。
- 每圈借助真值进行匹配和强制传播，015/016 命中率提高至 13.26% / 18.65%，仍很低。真值辅助会掩盖部分自主推理困难，不能作为可部署策略。
- 同一窗口、相同状态、eval 模式下，单窗口和批窗口路径的位置/logit 最大差为 0；去除标签后也为 0。改变俯仰角输入会改变输出，因此没有发现该维完全被忽略。这里只排除这些具体检查中的路径差异和标签依赖，不证明全部实现无误。

## 已修正的配置偏差

上游批训练逻辑为 DDP 梯度同步强制第一个片段的前两次传播使用真值辅助，但在单 GPU 中同样生效。真实训练调用处的回归测试请求概率 0，修正前实际为 `[True, True, False, False]`。

现在仅在 `torch.distributed.is_initialized()` 为真时保留上游强制行为；单 GPU 服从传入概率。回归测试修正后为 `[False, False, False, False]`，已经通过。修改纳入 `prepare_upstream.py`，本地及云端 B02 隔离副本同步修正，第一阶段及原始上游不修改。

## 三组等预算固定片段实验

三组均从 pilot02 权重开始、相同随机种子、相同 train_001 第 100–103 圈，共 104 个真值点；Adam 学习率 5e-5，300 次更新，仅改变辅助规则。每次验收在 eval 模式自主推理；另以 train_015 第 100–119 圈共 570 个真值点检查跨文件表现。

| 规则 | 拟合片段自主命中率 | 拟合片段精确率 | 另一文件命中率 | 另一文件精确率 |
| --- | --- | --- | --- | --- |
| 旧规则：前两帧强制，后续概率 .5 | 92.31% | 97.96% | 4.56% | 25.24% |
| 修正规则：全部按概率 .5 | 91.35% | 97.94% | 4.56% | 24.76% |
| 完全不使用真值辅助 | 93.27% | 97.98% | 4.21% | 19.05% |

三组共 900 次短更新，约 263 秒后正常结束，没有继续长训练。旧规则也能学会固定片段，修正并没有在这组实验中显著改善跨文件效果，因此不能宣称该配置偏差是主导根因。完全关闭辅助同样不能解决问题。

## 下一步与边界

已经确认模型能在真实 B02 小片段上学会目标点及其定位；之前 1000 步模型在其训练场景的新片段也很弱，不能简单归结为“只在开发集过拟合”。现在更应检查它是否学到了跨片段规律，而不是只记住位置。

建议固定评估集和推理阈值，先从若干训练片段逐级增加覆盖，每个阶段同时报告见过片段、同文件未见片段、不同文件的自主效果。在固定片段集上等预算比较模拟权重初始化与随机初始化，验证迁移是否真正有益；如有必要，再单独比较回归预测位置和以当前原始点为候选的方案。每次只改一个因素，不把这些假设写成已证实根因。

当前默认基线、推理阈值和已发布查看器结果均保持不变。诊断权重只在云端 `runs/b02-stage2-diagnosis/fixed-fit/` 保存，不作为改进模型发布。

本地原始记录：`runs/b02-stage2-diagnosis/frozen-probes.json`、`fixed-fit-report.json`。所有诊断脚本置于本目录的 `diagnostics/`，与常规训练入口区分。复现原始旧调度结果时可使用 fixed_fit.py 中的 legacy 对照，它在单次实验内恢复旧行为。
