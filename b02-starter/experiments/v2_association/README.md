## 可训练模型

`features.py` 将历史观测、速度、可信命中与当前候选的几何残差、相对时间、Amp/SNR 组成
40 维航迹特征和 20 维边特征。`model.py` 同时学习真实边与拒配的残差代价；最后一层初始化为零，
使训练前的关联与 v1 一致。所有标准化统计仅从拟合集计算。

先固定 v1 的出生、确认、门控、输出门限和状态更新，只改变关联代价。标签由历史真实身份及
当前候选真值产生，混杂身份前缀不作为确定监督。每场景抽取八段八帧，特征生成仍完整回放之前的所有圈。

两种子首轮为 20261116、20261117，分别最多 8000 步，保存 0／1000／3000／8000 检查点。
校准行分类准确率只能辅助诊断；采用必须看完整时序回放。先用固定的 train_032／train_050
监测，再对固定候选验证全部八个校准场景。不会凭训练步数或单个漂亮片段升级 v1。

运行环境需 PyTorch、NumPy、SciPy。仓库根目录执行：

```bash
python -m unittest discover -s tests -p 'test_v2*.py'
python experiments/v2_association/run_stage1.py --data YOUR_DATA.zip --out runs/v2-rules
python experiments/v2_association/prepare_pairs.py --data YOUR_DATA.zip --out runs/v2-pairs
python experiments/v2_association/train.py --pairs runs/v2-pairs --out runs/v2-train-20261116 --seed 20261116 --steps 8000
python experiments/v2_association/evaluate.py --data YOUR_DATA.zip --pairs runs/v2-pairs --checkpoint runs/v2-train-20261116/step-08000.pt --out runs/v2-calibration --reference runs/v2-rules/v1/summary.json --preview
```

`evaluate.py` 缓存冻结点模型分数，只计关联耗时，不能当作完整提交性能验收。
它默认仅允许登记的内部校准文件。查看器使用原有 `b02.visualize.export_viewer`，预先固定展示 train_032，避免按效果挑片段。
原始轨迹、训练张量、模型检查点保存在本地／云端结果目录，不上传 Git。

执行分工更新：本路线由用户统一推进，不以多人顺序交接为前提。3090 足够当前关联头实验；是否更换大显卡取决于后续模型和实测瓶颈。

联合模型校准行准确率约 95%，但真实回放仍退化。它大量拒绝内部杂点匹配，改变了原先起批和延续的分布；
改进不能只按行准确率衡量。只在真实延续存在的行训练候选排序，8000 步的两种子回放也未显示提升。
该目标的行损失在 1000 步优于 8000 步，记录在检查点历史中，不能概括为“训得越久越好”。

本轮区分了两类监督：原始物理身份、同一物理目标重复航迹中的连续输出所有者，两种子均未显示采用收益。
`prepare_pairs.py --label-mode continuity` 仅按过去已输出的真值支持、过去历史及年龄选择所有者，其他重复候选监督为拒配；
当前真值只判断正确点是否在候选中，不使用未来标签。它是训练标签的对照，不是推理时用真值改 ID。

另外实现 `context.py` 的局部群体关系：在当前高可信点的几何邻接图中计算相对位置、幅度／SNR 中心差和相对秩，
让模型有机会抵消邻近目标的共同波动。它不使用 PntID、真值编号、输入行序或绝对时间；
不会假定所有雷达目标都具有这种规律，须用未参与拟合的完整场景验证。
该分支为 60 维历史、50 维边，使用单独特征版本和训练张量，不能混加载旧关联检查点。

条件配对目标使用 `train.py --objective pair_ranking`，完整生成群体特征使用
`prepare_pairs.py --context --score-cache EXISTING_PAIRS`。缓存只复用同一冻结点模型的分数。
`evaluate.py --strategy rank_only` 保持拒配代价和单候选代价，针对多候选行附加相对排序惩罚；
`trusted_rank` 进一步只改变过去至少三次强证据的航迹。二者均须完整回放验证，未自动替代 v1。
