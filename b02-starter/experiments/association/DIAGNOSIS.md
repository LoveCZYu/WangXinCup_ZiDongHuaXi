# 固定版本的跟踪瓶颈诊断

当前路线的主要瓶颈是身份关联和航迹管理。增加点分类训练步数、微调输出阈值已有较小收益，现有证据不足以判断整个跟踪框架的理论上限。

本轮仅使用原先的 8 个内部校准文件与两个既定种子。固定 8000 步、0.50／0.05、历史三圈、关联分数权重 0.50，没有增加训练或搜索参数。两种子的全部逐航迹非耗时统计均复现原 GPU 结果。以下总分属于内部校准，两种子均值为 79.98；上一轮完整 30 文件开发集的 78.95 属于另一统计范围。

## 主要证据

两个种子各回放 999 条相同真值航迹。约 69.57% 的航迹用过多个输出 ID，承载真值点的输出 ID 中有 33.71% 接过多个真值目标。后一项按场景、种子分别统计，未把不同文件中的相同数字 ID 混合。

相邻两次命中的输出 ID 不同记为一次变号，共 8208 次。变号时旧 ID 的状态如下。

| 状态 | 次数 | 占变号比例 |
| --- | ---: | ---: |
| 已过期删除 | 449 | 5.47% |
| 仍存在，本圈未匹配 | 3561 | 43.38% |
| 匹配了另一个真值目标 | 3789 | 46.16% |
| 匹配了已知杂点 | 378 | 4.61% |
| 匹配了属性未确定点 | 31 | 0.38% |

94.53% 的变号发生时旧 ID 仍存在。84.66% 的变号中，新接管的 ID 在上一次命中时就已经建立；79.76% 的变号发生在同一真值相邻两次观测之间，中间没有遗漏该真值观测。这支持并存航迹竞争和身份串接为主要现象，延长 `max_missed` 不应直接作为首选改法。

本地计分没有单列输出 ID 的身份纯度，因此另保留混合 ID 诊断，帮助发现总分未充分反映的串轨。变号统计描述发生时的状态，不能独自证明某个改法能提高成绩。

## 漏点发生在哪一层

两个种子合计观测 316530 个真值点，其中 298897 个输出，17633 个未输出。同一数据重复两个种子属于对照次数，不是新增独立样本。

| 漏点归因 | 点次 | 占所有漏点 |
| --- | ---: | ---: |
| 关联及起批阶段未产生已确认输出 | 13820 | 78.38% |
| 已有已确认输出，但被输出阈值过滤 | 3813 | 21.62% |

前一类包含 3851 个发生在真值最初两次观测时的起批等待，不应全视为异常。其余主要为起步后重新建立候选的 7309 次、待确认航迹的 2654 次；只有 6 次没有获得新候选容量，扩大候选容量并非当前重点。

已输出过该真值、随后在过滤前漏点的情况中，5026 次的前一个输出 ID 预测门不包含当前真值点，1221 次在门内但未分配，315 次虽在门内但被代价阈值排除，912 次旧 ID 已不在当前状态中。门外现象可能来自运动预测误差，也可能来自旧 ID 已被其他目标或杂点带偏；不能据此直接断言放宽门限就是解法。

## 真值对照

以下只改已有输出的取舍或计分身份，不反馈到跟踪器状态，不是可以部署的方案。

| 对照 | 点命中率 | 连续子分 | 本地总分 |
| --- | ---: | ---: | ---: |
| 当前固定版本 | 94.429% | 73.086 | 79.981 |
| 当前输出去掉全部已知杂点及未确定点 | 94.429% | 73.086 | 80.593 |
| 保留过滤前输出中的全部真值点，去掉其余点，ID 不变 | 95.634% | 74.045 | 81.405 |
| 当前命中点和杂点不变，用真值统一目标 ID | 94.429% | 94.054 | 92.852 |
| 过滤前真值点全部保留，并用真值统一 ID | 95.634% | 95.309 | 94.419 |

身份统一对照比当前增加 12.871 分，单纯清除当前输出杂点增加 0.612 分。连续子分与 100 的差距中，约 77.91% 可由该身份统一对照消除。恢复所有过滤前已关联真值点只追回约 1.205 个百分点的点命中率。

这些方案不是最优筛选器或真实模型的上界。特别是保留全部真值点也会保留额外 ID，而局部计分对新增 ID 敏感，所以不能把 81.405 当作框架上限。相反，真值统一 ID 消除了实际模型未解决的身份歧义，也不能把 92.852 当作可承诺成绩。

## 代码为什么会形成这个瓶颈

当前神经网络学习每个点的目标分数，输入为当前及过去五圈的局部几何特征，没有输入某条候选航迹的独立历史。分配代价为归一化预测距离平方加 `0.50 × (1 − 当前点分数)`。

置信度项只依赖点，不依赖航迹。两条航迹匹配同一组两个点时，无论怎样交换配对，两个置信度项之和都相同。因此模型能帮助选择匹配哪些点、是否放弃匹配，却无法直接学习同一组目标点分别属于哪条航迹。两个目标都高分时，身份区分主要仍取决于固定运动距离。

此外，`process_circle` 先完成匹配、更新位置及速度、累加命中、创建候选，`OutputGate` 随后才决定最终输出。两个种子合计 354518 次已确认航迹的已知杂点匹配被最终过滤，但这些匹配此前已经参与内部状态更新。输出减杂并不等于内部跟踪已经清除了杂点影响。该路径有明确代码依据，其具体改进收益仍需单变量对照验证。

## 下一轮实验顺序

1. 先针对并存航迹竞争及串轨做小规模对照，例如轨迹历史兼容性、重复候选管理与基于不确定度的预测。检查变号率、混合 ID 和连续子分，同时约束漏点及杂点。
2. 单独测试低置信匹配如何影响内部状态更新，保持其他规则固定，确认隐藏杂点更新是否是可改善的原因。
3. 若规则对照收益有限，再训练依赖航迹历史的匹配分数，让模型学习“这个点属于哪条航迹”。继续增加当前点分类器的训练步数优先级较低。

两种子内部校准通过后再冻结候选，进行完整开发集验证。继续保留 4000 步与 8000 步对照，封存测试集保持未使用。

## 运行与产物

```bash
timeout --signal=TERM --kill-after=10s 660s python experiments/association/diagnose.py \
  --project . --data /path/to/point-expanded-data.zip \
  --steps-run runs/b02-association-steps01 --threshold-run runs/b02-association-threshold02 \
  --out runs/association-diagnosis-new --device cuda --threads 4 --seconds 600
```

GPU 全量诊断用时 134.43 秒，结束后无 GPU 计算进程，没有新增训练。此前本地 CPU 核验在 178 场景少输出 1 个杂点、真值命中一致，最终诊断统一采用原 GPU 环境下逐场景完全复现的结果。

运行目录含 `manifest.json`、`report.json`、`derived.json`、逐场景归因、真实回放及六组对照计分表。真值只用于诊断分类与对照，未进入真实模型输入、匹配或状态更新。诊断计时包含记录开销，不能代替提交环境性能验收。源码与结果说明可共享，原始数据、检查点和运行产物保留本地。
