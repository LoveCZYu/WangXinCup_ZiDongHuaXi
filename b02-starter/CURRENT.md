## 冻结过程与验证

在原 8 文件内部校准集上，只试了六组预先固定的输出门限，没有追加训练。没有方案完全通过逐种子约束。0.525／0.05 的校准均值杂点略低、总分最高，但第二个种子多出 64 个杂点，故先作为备选固定下来，再做完整开发验证。

在读取开发文件之前已记录备选、配置 SHA-256 及采用条件。开发结果没有用于继续调参。最终两个种子均通过预定开发验证条件，才将这份冻结配置设为当前推荐。11.14 模型选定时未使用 30 个封存场景；11.16 公开 A 榜推理后的独立保留范围调整见本页顶部。

- 新统一运行入口在云端复现原参考的 015 统计及备选的 032 校准统计，非耗时字段逐项一致。
- 发布推理权重与完整训练检查点逐张量相等，加载时检查 SHA-256、步数及种子。
- 所有真实回放输出经过原始点身份、唯一性及正整数输出 ID 检查；标签只用于计分。
- 本机官方收发联调使用当前配置，在 `train_005.dat` 完整处理 719 圈，状态 `success`，输出 19332 个点。该结果证明收发链路可用，不代替官网评分或资源验收。
- 最后一次校准云端约 159.55 秒，完整开发验证约 506.05 秒，结束后无 GPU 计算进程。官方联调约 191.65 秒。

## 一份主配置、一份参考

`profiles/current.json` 固定种子 20261112，供队友日常运行和联调。种子在开发验证前已指定，不是从开发结果中选出的较优种子。模型有 9153 个参数，当前推理文件 39885 字节。

需要回归原 8000 步模型时使用：

```text
python -m b02 replay "你的训练数据.zip" --tracker point-scorer --profile profiles/reference.json --scene train_015 --out runs/reference-015
```

最初简单基线使用 `--tracker baseline`。完整训练检查点和历史实验留作复查，日常运行无需挑选它们。
